AWS 비용 항목 중 "NAT Gateway - Data Processed"가 유독 큰 경우의 원인과 해법을 공부했습니다.

## S3도 "인터넷"이다

프라이빗 서브넷의 인스턴스가 S3에 접근하면, 경로는 기본적으로 NAT 게이트웨이 → 인터넷 게이트웨이 → S3입니다. S3가 같은 리전에 있어도 퍼블릭 엔드포인트로 나가는 구조라, NAT의 데이터 처리 요금(GB당 $0.045 수준)이 전 트래픽에 붙습니다. 로그 적재, 백업, 데이터 파이프라인처럼 S3를 무겁게 쓰는 워크로드면 이것만으로 월 수백~수천 달러가 나옵니다.

## 게이트웨이 엔드포인트: 무료 직통로

S3와 DynamoDB에는 게이트웨이 타입 VPC 엔드포인트가 있습니다. 라우팅 테이블에 항목을 추가해 해당 서비스行 트래픽을 AWS 내부 경로로 직접 보내는 방식이고, 시간당 요금도 데이터 처리 요금도 없습니다.

```hcl
resource "aws_vpc_endpoint" "s3" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.ap-northeast-2.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = [aws_route_table.private.id]  # 프라이빗 RT에 연결
}
```

적용하면 라우팅 테이블에 S3 prefix list 경로가 생기고, 이후 S3 트래픽은 NAT를 건너뜁니다. 애플리케이션 변경은 없습니다. 같은 방식이 DynamoDB에도 그대로 적용됩니다.

부가 효과로 보안도 좋아집니다. 엔드포인트 정책으로 "이 VPC에서는 특정 버킷만 접근 가능" 같은 제어를 걸 수 있고, S3 트래픽이 인터넷 경로를 아예 타지 않게 됩니다. 참고로 인터페이스 타입 엔드포인트(PrivateLink)는 시간당+데이터 요금이 있으므로, S3/DynamoDB는 게이트웨이 타입이 정답입니다.

## 정리

- 프라이빗 서브넷 + S3 헤비 워크로드 = NAT 요금 폭탄의 전형적 조합이다.
- S3·DynamoDB용 게이트웨이 엔드포인트는 무료이고 설정은 라우팅 테이블 한 줄이다.
- 비용 절감과 동시에 트래픽이 AWS 내부망에 갇히는 보안 이득까지 따라온다.
