짧은 입력 문자열 하나로 서버 CPU를 100%로 만드는 공격, ReDoS를 공부했습니다. 놀랍게도 원인은 평범해 보이는 정규식입니다.

## 파국적 백트래킹

전통적인 정규식 엔진(대부분의 언어 내장)은 백트래킹으로 매칭합니다. 문제는 수량자가 중첩된 패턴입니다.

```javascript
// 위험한 패턴들
/(a+)+$/
/(a|a)*$/
/^(\w+\s?)*$/
```

`(a+)+`에 `"aaaaaaaaaaaaaaaaaaaaX"`처럼 "거의 매칭되다가 마지막에 실패"하는 입력을 주면, 엔진이 a들을 그룹에 나눠 담는 모든 경우의 수를 시도합니다. 이 경우의 수가 입력 길이에 따라 지수적으로 늘어납니다. 30~40글자짜리 입력 하나가 CPU를 몇 초씩 100%로 점유하고, 이런 요청 몇 개면 서버가 응답 불능이 됩니다. 이메일·URL 검증 정규식이 사용자 입력을 직접 받는 경우가 특히 위험합니다.

## 방어

```javascript
// 1. 중첩 수량자를 없애고 명확하게
//    나쁨: /^(\w+\s?)*$/
//    좋음: /^\w+(\s\w+)*$/   (같은 의도, 백트래킹 폭발 없음)

// 2. 선형 시간이 보장되는 엔진 사용 (RE2 계열)
const RE2 = require("re2");
const re = new RE2("(a+)+");   // 백트래킹 자체가 없어 지수 폭발 불가

// 3. 입력 길이 제한 (심층 방어)
if (input.length > 256) return reject();
```

RE2 같은 엔진은 유한 오토마타 기반이라 어떤 입력에도 선형 시간을 보장합니다(대신 역참조 등 일부 기능 미지원). 코드 리뷰나 CI에 정규식 안전성 검사 도구를 넣어 위험 패턴을 미리 잡는 것도 좋은 습관입니다. 사용자 입력을 받는 정규식이라면 길이 제한은 기본입니다.

## 정리

- 중첩 수량자 `(x+)+`, `(x|x)*`는 ReDoS의 시그니처다.
- 패턴을 선형적으로 다시 쓰거나, RE2 엔진으로 백트래킹 자체를 없앤다.
- 사용자 입력 정규식엔 길이 제한을 심층 방어로 항상 건다.
