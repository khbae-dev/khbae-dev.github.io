코드 실행 기능이 있는 개발 도구(노트북류)를 인증 없이 외부에 노출했을 때의 위험을 공부했습니다. 최근 보고된 미인증 RCE 취약점 사례가 계기였는데, 원리는 특정 제품에 국한되지 않습니다.

## 코드 실행 = 최고 등급의 권한

주피터, marimo 같은 대화형 노트북은 본질적으로 "임의 코드를 실행하는 서버"입니다. 이 엔드포인트가 인증 없이 열려 있으면, 접근한 누구나 서버에서 셸 명령을 실행할 수 있습니다. `os.system(...)` 한 줄이면 끝입니다. 로컬 개발 편의로 만든 도구를 `0.0.0.0`에 바인딩해 배포하거나, 방화벽 규칙 실수로 포트가 열리는 순간 공격 표면이 됩니다. 공개 후 몇 시간 만에 스캐너가 발견해 실제 공격으로 이어진 보고들이 있습니다.

## 3겹 방어

```python
# 1. 토큰 필수화: 실행 엔드포인트에 인증을 강제
#    (예: 실행 시 --token 옵션, 또는 리버스 프록시에서 인증)

# 2. 기본 바인딩을 localhost로
#    나쁨: 0.0.0.0 (모든 인터페이스 = 외부 노출)
#    좋음: 127.0.0.1 (로컬 전용) + 필요한 접근은 SSH 터널/VPN
server.run(host="127.0.0.1", port=8888, token=REQUIRED)

# 3. 최신 패치 유지: 알려진 CVE는 버전 업으로 닫는다
```

원칙은 계층 방어입니다. 어느 하나가 뚫려도 다음이 막습니다. 여기에 네트워크 레벨에서 개발 도구 포트를 인터넷에 절대 노출하지 않는 정책(보안 그룹 인바운드 최소화)과, 실행 서버를 사용자 데이터·비밀에 접근할 수 없는 격리 환경에서 돌리는 것까지 더하면 더 견고합니다.

## 정리

- 코드 실행 기능을 가진 도구의 인증 부재는 사실상 공개 셸을 여는 것과 같다.
- 토큰 필수화 + localhost 기본 바인딩 + 패치, 세 겹을 기본값으로 둔다.
- "내부용이니까"라는 가정은 방화벽 실수 한 번에 무너진다. 노출 자체를 막는다.
