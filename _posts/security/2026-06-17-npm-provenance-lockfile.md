의존성 공급망 공격을 공부했습니다. 내가 쓰는 유명 패키지의 특정 버전이 탈취돼 악성 코드가 심어지는 시나리오입니다.

## 신뢰의 사슬이 끊기는 지점

npm 생태계에서 우리는 수백 개 패키지를 "이름과 버전"만 보고 신뢰합니다. 공격자가 메인테이너 계정을 탈취하거나 typosquatting으로 유사 이름 패키지를 올리면, 설치하는 순간 악성 코드가 실행되거나 번들에 섞여 들어갑니다. 문제는 "이 패키지가 정말 그 저장소의 그 소스에서 빌드됐는가"를 확인할 방법이 없었다는 점입니다.

## provenance: 출처를 증명한다

npm provenance는 패키지가 어떤 저장소의 어떤 커밋에서, 어떤 CI로 빌드됐는지를 서명된 증명으로 연결합니다. 게시자는 CI에서 provenance와 함께 배포하고, 설치자는 그 증명을 검증할 수 있습니다.

```bash
# 게시(메인테이너): CI에서 provenance 첨부
npm publish --provenance

# 소비(우리): 정확 버전 + 무결성 검증
npm ci                      # lockfile의 integrity 해시를 강제 검증
```

소비하는 쪽의 방어도 함께 챙깁니다.

- 정확 버전 핀: `^1.2.3`(범위) 대신 lockfile로 정확 버전을 고정해, 예고 없는 새 버전이 자동 유입되지 않게 합니다.
- `npm ci`: package-lock.json의 integrity(SHA-512) 해시와 일치하지 않으면 설치를 거부합니다. 레지스트리에서 내용이 바뀌면 잡힙니다.
- 릴리스 지연: 새 버전을 즉시 올리지 않고 며칠 관망하면, 그사이 발견·철회되는 악성 버전을 피할 수 있습니다.

## 정리

- 의존성은 "이름·버전"만으로 신뢰하기엔 공급망 위험이 크다.
- provenance는 "이 아티팩트가 그 소스에서 나왔다"는 출처 증명을 더한다.
- 정확 버전 핀 + npm ci 무결성 검증으로 설치 단계에서 변조를 걸러낸다.
