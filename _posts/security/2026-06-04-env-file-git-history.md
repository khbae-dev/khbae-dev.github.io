가장 흔한 시크릿 유출 경로를 정리했습니다. `.env`를 실수로 커밋하는 것입니다. 파일을 지우는 것만으로는 해결되지 않는다는 게 핵심입니다.

## 커밋은 스냅샷이 아니라 역사다

git은 매 커밋을 히스토리에 영구 기록합니다. `.env`를 커밋한 뒤 다음 커밋에서 삭제해도, 그 파일은 이전 커밋에 그대로 남아 있습니다. 저장소를 clone한 누구나, GitHub의 커밋 히스토리에서 그 시점을 열어 키를 볼 수 있습니다. 저장소가 공개였다면 봇이 몇 분 안에 스캔해 갑니다. 즉 "커밋된 순간 이미 유출됐다"고 가정해야 합니다.

## 절차: 추적 해제 → 재발급 → 히스토리 정리

```bash
# 1. 추적에서 빼고 앞으로 커밋 안 되게
git rm --cached .env
echo ".env" >> .gitignore
git commit -m "Remove .env from tracking"
```

여기까지는 "앞으로"만 막습니다. 이미 유출된 키에는 두 가지가 더 필요합니다.

```bash
# 2. (가장 중요) 노출된 모든 키를 즉시 재발급/폐기
#    API 키, DB 비밀번호, 토큰 — 히스토리에 남은 값은 죽은 값으로 만든다

# 3. 히스토리에서 파일 자체를 제거 (선택, 협업 시 조율 필요)
git filter-repo --path .env --invert-paths
#    이후 강제 푸시 + 팀원 재클론 필요
```

순서가 중요합니다. 히스토리 정리(3번)는 시간이 걸리고 강제 푸시가 필요한 반면, 키 재발급(2번)은 즉시 위험을 무력화합니다. 그래서 재발급이 최우선입니다. 히스토리를 아무리 깨끗이 지워도 이미 누군가 클론했다면 그 사본에는 키가 남아 있으니, "키를 죽이는 것"만이 확실한 조치입니다.

예방책으로는 커밋 전 시크릿 스캐너(gitleaks, pre-commit 훅)를 걸어두는 게 최선입니다.

## 정리

- 커밋된 시크릿은 파일 삭제로 사라지지 않는다. 히스토리에 영구히 남는다.
- 최우선 조치는 히스토리 정리가 아니라 노출된 키의 즉시 재발급이다.
- gitignore + pre-commit 스캐너로 애초에 커밋되지 않게 막는 게 제일 싸다.
