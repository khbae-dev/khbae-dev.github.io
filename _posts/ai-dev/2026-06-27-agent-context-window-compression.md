자율 에이전트를 오래 돌렸더니 토큰 비용이 폭발한 사례를 공부했습니다. 스텝 수에 비례가 아니라 제곱으로 늘어난 게 핵심이었습니다.

## 왜 O(N²)인가

에이전트는 매 스텝마다 지금까지의 대화·관찰·행동 히스토리를 컨텍스트에 담아 모델을 호출합니다. 순진하게 구현하면 매 스텝에 "전체 히스토리"를 다시 보냅니다.

```
스텝 1: 토큰 100 전송
스텝 2: 토큰 200 전송 (히스토리 누적)
스텝 3: 토큰 300 전송
...
스텝 N: 토큰 100N 전송
```

총 전송 토큰은 100 × (1+2+...+N) ≈ O(N²)입니다. 스텝이 수백 개인 장시간 작업이면 후반 스텝 하나가 수만 토큰이 되고, 총비용은 스텝 수의 제곱으로 뜁니다. 63시간짜리 작업이 수천 달러가 되는 경로입니다. 게다가 컨텍스트 상한에 부딪히면 작업이 아예 멈춥니다.

## 컨텍스트 상한을 고정한다

핵심은 "히스토리를 무한히 쌓지 않고 상한을 두는" 겁니다.

```python
def build_context(history, budget_tokens=8000):
    recent = []
    used = 0
    # 최근 스텝은 원본 그대로 (슬라이딩 윈도우)
    for step in reversed(history):
        t = count_tokens(step)
        if used + t > budget_tokens:
            break
        recent.append(step); used += t
    recent.reverse()

    # 윈도우를 벗어난 오래된 스텝들은 요약으로 압축
    old = history[: len(history) - len(recent)]
    summary = summarize(old) if old else ""

    return summary, recent
```

- 슬라이딩 윈도우: 최근 K 스텝만 원본으로 유지합니다. 대부분의 다음 행동 결정에는 최근 맥락이 가장 중요합니다.
- 요약 압축: 윈도우를 벗어난 오래된 스텝은 핵심만 요약해 한 덩어리로 유지합니다. 목표·중요 사실 같은 장기 기억은 별도 슬롯에 고정합니다.

이러면 매 스텝 전송 토큰이 상한(budget) 근처에서 평평해져 총비용이 O(N)으로 내려갑니다. 외부 메모리(벡터 스토어)에 상세를 저장하고 필요할 때만 불러오는 방식으로 더 확장할 수 있습니다.

## 정리

- 전체 히스토리 재전송은 토큰 비용을 O(N²)로 만든다. 장시간 에이전트의 조용한 파산 원인.
- 슬라이딩 윈도우(최근 원본) + 오래된 것 요약으로 컨텍스트 상한을 고정한다.
- 목표·핵심 사실은 별도 고정 슬롯, 상세는 외부 메모리로 분리하면 더 안정적이다.
